# トキワ ローカルサーバー

UIとSQLite DB(`db/tokiwa.db`)をつなぐローカルAPIサーバー。
**Python標準ライブラリのみ**で動作(追加インストール不要)。

## 起動

```bash
# 1. DBを用意(未作成なら)
python3 scripts/import_to_sqlite.py

# 2. サーバー起動
python3 server/app.py            # http://localhost:8760
python3 server/app.py 9000       # ポート指定
```

ブラウザで http://localhost:8760/ を開く。ログイン後、通常どおり操作できる。
埋め込み版(tokiwa-ui.html を直接開く)と違い、**データは tokiwa.db から読み、
会計確定は tokiwa.db に保存される**(再読み込みしても残る)。

## エンドポイント

| メソッド | パス | 内容 |
|---|---|---|
| GET | `/` | UIを配信。DBから組み立てたデータを埋め込む |
| GET | `/api/data` | 画面用データ(JSON) |
| POST | `/api/checkout` | 会計を保存(伝票+明細+在庫引落+ポイント加算) |
| GET | `/api/health` | 稼働確認 |

## 構成

- `app.py` … HTTPサーバー(ルーティング・UI配信)
- `db_query.py` … DBから画面データを組み立て / 会計を書き込む

## 位置づけ

正式運用(Windows単機)はこのサーバーをローカル起動しブラウザで開く構成を想定。
将来デスクトップアプリ(Electron等)や周辺機器(COMポート)制御を足す場合も、
このAPI層はそのまま流用できる。

## 現状の制約(今後の課題)

- 顧客・商品の検索は、DBから読んだ全件を画面側で絞り込む方式(数千件は快適)。
  数万件規模になったらサーバー側の検索・ページングに切り替える
- 認証・権限は未実装(app_users テーブルは用意済み)
- 会計のPOSTは山田太郎(ID 1)固定のデモ結線。顧客選択との連動は次段階

## このテストの読み方

各項目は必ず **「操作」** と **「合格」** の2行を持つ。

- **操作** … そのとおりに触る。手順以外のことはしない
- **合格** … この状態になったら合格。**ならなければ不合格**

判断に迷わないよう、合格の条件は「正しく動く」ではなく **目で見て確かめられること**
(件数が減る・この文字が出る・この値になる)で書いてある。曖昧に感じたら合格にせず、
何がどう違ったかをメモして次へ進む。

### 記入のしかた
- 合格 → `- [x]` にする
- 不合格 → `- [ ]` のまま残し、**そのすぐ下に「→ 実際どうなったか」を書く**
- そもそも試せない(機器が無い等) → `- [-]` にして理由を書く

## 11. 返品・監査

> ★返品の集計ルール(2026-08-06 顧問税理士の確認で確定):
> **当日中の取消=訂正**(日報から消える) / **日をまたいだ取消=返品**(売った日の日報は
> そのまま。返品した日の日報にマイナス行が載る)。締めた日の日報は後から変わらない。

- [ ] **11-1 当日中の取消は「訂正」として消える**
  - 操作: 今日会計した明細を、**今日のうちに**取消す(返金方法を選ぶ)
  - 合格: ①今日の日報からその売上が**消える**(マイナス行も出ない)
    ②現金締めにも残らない ③商品の在庫が**戻る**
  - 理由: 締め前の打ち間違いは最終状態だけ残ればよい(5回打ち直したら5回目だけ出る)

- [ ] **11-2 ★日をまたいだ返品は両方の日報に正しく載る**
  - 操作: **昨日以前に**会計した明細を今日返品する(返金方法=現金を選ぶ)
  - 合格: ①**元の日の日報は変わらない**(売上がそのまま残っている)
    ②**今日の日報にマイナス行**が載り、「◯◯◯◯-◯◯-◯◯購入分の返品」の注記と
    「返金(現金)」が出る ③今日の現金締めが返金分だけ**減る**
    ④元の日の現金締めは**変わらない** ⑤在庫が戻る
  - 理由: 締めた日の帳簿を後から変えないため(税理士確認済み)。ここが今回の要

- [ ] **11-2b 返金方法を選べる**
  - 操作: 取消のダイアログを開く
  - 合格: 返金方法(現金/クレジット/銀行振込/ポイント/その他)のボタンがあり、

  - 合格: お客様控と店控の2枚が出る

- [ ] **11-4 ポイントも戻る**
  - 操作: ポイントが付いた会計を返品する
  - 合格: 付与されたポイントが**取り消される**(残高が元に戻る)

- [ ] **11-5 取消の記録が残る**
  - 操作: 購入履歴の「取消済みも表示」をONにする
  - 合格: 取消した明細が取消日つきで見える(既定はOFF)

- [ ] **11-6 番号なし明細の品名を後から直せる**
  - 操作: 購入履歴で、商品番号のない明細を**ダブルクリック**して品名を直す
  - 合格: 品名が直る。**金額は変えられない**。
    在庫品の明細と取消済みの明細は**修正できない**(サーバーが拒否する)

- [ ] **11-7 売上を別のお客様に付け替えられる**(v0.34.15で追加)
  - 操作: 顧客Aの購入履歴で **「顧客変更」** を押す → 出てきた**伝票の中身(明細・合計)**を確認 →
    付け替え先に顧客Bを選び、担当者と理由を入れて「付け替える」
  - 合格: ①**Aの履歴からその売上が消え、Bの履歴に同じ金額で載る**
    ②**金額が変わっていない**(Bの累計購入額がAで減った分だけ増える)
    ③**A・B両方の基本情報のメモに付け替えの記録**(日付・担当者・理由)が残る
    ④ポイントが付いていた売上なら、**Aのポイント残高が減りBが増える**

  - 注意: **伝票まるごと動く**(同じ会計の他の明細も一緒に移る)。実行前に画面に出る
    明細一覧で確認すること

## 17. 懸案・許容事項(承知の上で運用に入るもの)

**これらは不合格に数えない。**ただし「知らなかった」で運用に入らないよう明記しておく。

### 17-1 値札のバーコードが読み取りにくい(★運用でカバーすると決定・2026-08-06)

- **症状**: 印刷した値札のバーコードをハンディスキャナで読むと、12枚中5枚程度しか読めない
- **原因**: 台紙のバーコードが規格(80%)に対して**72%と物理的に小さい**。
  v0.32.1で幅を27mmまで広げて3枚→5枚に改善したが、これ以上はコード側で対処できない
- **決定**: **台紙は作り直さず、この状態で運用に入る。**読めない分は運用でカバーする
- **運用のしかた**: 読めない場合は台紙に印字された**管理番号を手入力**する。
  棚卸し画面は5回連続で失敗すると手入力を案内する(§5-5)。
  **棚卸しは「スキャンで拾えた分＋手入力」で進める作業と考える**
- **将来直すなら**: 台紙のバーコードを規格の80%以上で作り直す。
  そのときは §8-7 の読み取り枚数を再測定して改善を確認する

### 17-2 DM区分の表記に想定外の値がある可能性

- **症状**: xlsx取込は「dm送付有無」列の値をそのまま入れるため、`DM_NO_VALUES` に
  無い表記があると「送る」扱いになる
- **確認方法**: §7-10 の `diag_dm_flags.py` で拾い漏れを検出する
- **運用での回避**: 住所の記号(ＴＴＴ等)が二重の安全網になっている

### 17-3 詳細検索の上限は2000件

- 詳細検索の結果は2000件で打ち切られる。全顧客を対象にしたDM抽出では
  条件を分けて複数回に分ける

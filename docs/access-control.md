# アクセス制御(ログインIDごとの権限)設計メモ

**✅ v0.24.0 で実装済み(2026-07-22)。** 以下の設計どおりに実装した。
- ログイン: サーバーが未ログインにはログイン画面を配信。パスワードは本人が初回ログインで設定
  (PBKDF2ハッシュ。app_users.pass_hash)。セッションは app_sessions テーブル(60日で失効)。
- ロール: admin=管理者 / staff=社員 / part=パート(role列)。
- パート: 下代(cost_price)・在庫サマリの下代/粗利をサーバーが送らない。商品・在庫/設定画面
  非表示+商品登録/修正/削除/写真/マスタ編集/ランク更新のPOSTを403で拒否。
- 管理者のみ: 担当者マスタ(POST /api/staff)・ログインユーザー管理(/api/app_users, /api/app_user)。
  設定画面の「ログインユーザーと権限」から追加・役割変更・有効/無効・パスワードリセット。
  最後の有効な管理者の降格・無効化は禁止(ロックアウト防止)。
- 旧「店内共有モード」(PC単位のremote判定・TOKIWA_REMOTE)は下記の方針どおり削除済み。

## 目的(店舗の要望)
- 管理者 → 全て閲覧・編集可能
- パート → **仕入金額を見せない**、**商品登録・仕入登録をさせない**(仕入原価を知られないため)
- 社員 → 中間(運用に応じて決める)

## ロールと権限マトリクス(たたき台)
| 機能 | 管理者(admin) | 社員(staff) | パート(part) |
|---|:--:|:--:|:--:|
| 顧客・購入履歴 閲覧 | ✓ | ✓ | ✓ |
| レジ(会計) | ✓ | ✓ | ✓ |
| **在庫(商品・在庫)画面へのアクセス** | ✓ | ✓(運用次第) | **✕** |
| **仕入金額(cost_price=下代)の表示** | ✓ | ✓(運用次第) | **✕** |
| **在庫サマリの下代合計・粗利率の表示** | ✓ | ✓(運用次第) | **✕** |
| **商品登録・仕入登録** | ✓ | ✓(運用次第) | **✕** |
| 担当者マスタ・権限の管理 | ✓ | ✕ | ✕ |
※社員欄は運用が固まってから確定する。

## 最重要: サーバー側で強制すること(画面で隠すだけは不可)
トキワはサーバー＋ブラウザ型。UI(HTML/JS)で仕入金額を隠しても、ブラウザの開発者ツールや
APIを直接叩けば見えてしまう。したがって:
- **APIの応答(build_blob 等)から、権限の無いロールには cost_price 等を除外して"そもそも送らない"**。
- **商品登録・仕入登録などの操作は、サーバー側(POSTハンドラ)でロールを見て拒否**する
  (ボタンを消すのはUIの補助にすぎない)。

## 土台(すでにあるもの)
- `db/schema.sql` の `app_users(user_id, store_code, display_name, role, pass_hash, active)`。
  role は staff/manager/admin を想定。移行で宝飾ナビのログイン16名を取込済み(平文PWは入れていない)。
- 宝飾ナビ自身が権限フラグを保持: `d_systemuser` の `lngpermission` `lngmasterflg`
  `lngotheropeflg` `lngsiireflg`(=仕入表示可否)。必要なら役割定義の参考にする/引き継ぐ。

## ★実装時に「削除」する既存の仕組み(重要)
現在は「**どのPCから開いたか**」で画面を変える暫定方式が入っている(v0.10.0 店内共有モード)。
ログインのロール制御が入ればこれは**不要になるので削除する**。該当箇所:
- `server/app.py`
  - `_is_remote()`(client_address が localhost 以外か、または `?remote=1` で判定) … 83〜88行付近
  - `render_index(remote=...)` と `window.TOKIWA_REMOTE` の注入 … 51〜63行付近
  - 会計(checkout)を remote で拒否している分岐 … 128行付近
- `tokiwa-ui.html`
  - `if (name === "register" && window.TOKIWA_REMOTE)` によるレジ非表示 … 1318行付近
  - `if (window.TOKIWA_REMOTE)` のリモートUI分岐 … 2422行付近

置き換え方針: 「PC単位(remote)」→「ログインのロール単位」。
- レジの可否・商品登録の可否・仕入表示の可否は、**PCではなくログインしたユーザーのロール**で決める。
- 他PCからの利用制限が必要なら、それはネットワーク/ロールで表現する(PC判定は使わない)。
- 削除後、`window.TOKIWA_REMOTE` 参照が残っていないか grep で確認する。

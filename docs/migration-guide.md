# 【旧】xlsx(11台帳)からの移行手順

> ## ★このページの手順は本番では使いません(2026-07 に切り替え済み)
>
> **本番の取込は CSV です。手順は `docs/go-live-checklist.md` を見てください。**
>
> ```
> python scripts\import_csv.py data\real\csv
> ```
>
> 宝飾ナビからは2つの形でデータが出てきますが、**CSVの方が情報量が多い**ため
> そちらに乗り換えました。**中分類・脇石・タグ品名・DM備考はCSVにしかありません。**
>
> | | 中身 | 取込ツール | 今の役割 |
> |---|---|---|---|
> | **csv/** | 114テーブルの生ダンプ | **`import_csv.py`** | **本番** |
> | xlsx/ | 11台帳(まとめ版) | `import_to_sqlite.py` | 答え合わせ用 |
>
> `import_to_sqlite.py` は **`db/tokiwa.db` を作り直します**。本番稼働後に
> うっかり実行しないこと(取り込んだ実データが消えます)。
>
> このページは、xlsx側の構造と予行演習の記録として残しています。

宝飾ナビから吸い出した xlsx を、トキワのDB(db/tokiwa.db)に取り込む手順。
デモデータ(同じ11台帳構造)で予行演習済み。

## 0. 事前準備(データ受領時に確認)
- データ形式: xlsx(デモと同じ11台帳形式なら分析・移行ツールがそのまま使える)
- 11台帳: 顧客台帳 / 家族台帳 / 商品台帳 / 販売台帳 / 売掛台帳 / 売掛履歴 /
  ポイント台帳 / ポイントカード履歴 / アプローチ履歴 / メガネ処方箋台帳 / サービスポイント台帳
- カード磁気↔会員番号の対応表があれば別途受領(カード連携移行が楽になる)

## 1. 実データを置く(PC内のみ・GitHubには上がらない)
もらった xlsx 一式を **`data/real/xlsx/`** に入れる(`data/real/` は `.gitignore` 済み)。

```
data/real/
  csv/    … 宝飾ナビの生ダンプ。★本番の取込元
  xlsx/   … 11台帳。ここ
  images/ … 商品写真
```

★`data/real/` の直下に置いたままでも動きます(`scripts/_paths.py` が両方見る)。

## 1b. 取込のあとの「答え合わせ」に使う ★おすすめ

xlsxは取込には使いませんが、**取りこぼしの確認**に使えます。

```
python scripts\diag_real_xlsx.py
```

台帳ごとの**行数だけ**が出ます(中身の値は表示しないので実データでも安全)。
これを `import_csv.py` が最後に出す「取り込み件数」と見比べます。

**顧客・商品・売掛・ポイントは一致するはず**です。ズレていたら取りこぼしを疑う。
**販売台帳と処方箋はズレて正常**です(販売はトキワ側で伝票+明細に分けている。
処方箋は宝飾品の誤登録を除いている)。

また xlsx は「コード」と「その名前」が両方並んでいるため、**区分コードの正解表**
としても使えます(`python scripts\diag_kubun.py`)。続柄・支払方法などがこれで確認できます。

## 2. 分析(読み取りのみ・元データは無変更)
```
python scripts\analyze_real_data.py
```
→ `data/real/分析レポート.md` が出る。中身を共有 → 孤児データ・重複・商品参照切れ・
ポイント不一致・処方箋への宝飾品混入を確認し、クレンジング方針を決める。

## 3. 本番DBへ取り込み
```
python scripts\import_to_sqlite.py            # data/real/ を移行(db/tokiwa.db を作り直す)
```
- 和暦(西暦和暦コード 1明治〜5令和)を自動で西暦変換
- 販売台帳を伝票ヘッダ+明細に分割(伝票番号が空欄なら合成キーで採番)
- 処方箋は SPH/CYL/AX/ADD/PRI/BASE/PD/裸眼/矯正 まで取り込み、宝飾品の誤登録を判定
- 実行後に「取り込み件数」「参照整合性(孤立参照の検出)」「検証クエリ」を表示
- ※予行演習は `--demo`(data/demo を使用)。任意フォルダは引数で指定可

## 4. 確認
```
python server\app.py
```
→ http://localhost:8760/ を開き、顧客検索・購入履歴・ポイント・処方箋・売掛が
実データで正しく表示されるか目視。

## 既知の注意点 / 移行時の判断ポイント
- **列名は宝飾ナビの見出しに依存**: import_to_sqlite.py は見出し名で列を拾う。
  実データの見出しがデモと違う場合は、その台帳だけ取り込めない(エラーにはならず空になる)。
  → まず analyze_real_data.py の件数と、import の「取り込み件数」を突き合わせて欠落を検知する。
- **孤立データ**(顧客不明の履歴等)は取り込み時に顧客側へは繋がない。分析レポートで方針決定。
- **重複顧客**(氏名+電話一致)は自動統合しない。残すIDを決めて名寄せ(移行後の作業)。
- **サービスポイント台帳**は現状 point 系に集約していない(必要なら追加対応)。
- 移行後、必ず `db/tokiwa.db` のバックアップを取る(店外保管)。

- ✅ **処方箋の用途がコードのまま** → 1=常用/2=遠用/3=近用
- ✅ **性別の対応が逆だった(重大)** → 正解は 1=女, 2=男(diag_kubunで発覚)。ピアス(1=有,2=無)も修正

## B. 新機能の要望(実装優先順位を2026-07-15に確定。詳細は docs/roadmap.md 参照)
優先順位: **B-7(商品写真・最優先) → B-1 → B-5 → B-3 → B-2 → B-4 → B-6**
(番号は起票順のため実装順とは一致しない。以下も優先順に並べ替え済み)

### B-7. 商品画像の登録 ★最優先
- 理由(2026-07-15 相談): 実業務のフローは
  「仕入れ→**商品登録(写真を登録)**→登録確認/修正/削除→顧客が購入(写真閲覧)→
  購入履歴でも写真閲覧→返品(在庫に戻った後も写真が見えるか)」という一連の流れで、
  **入口の商品登録でつまずくと後工程を何度もやり直す**ことになる。そのため他の新機能より
  先に、この一連の流れをテストできる段階まで作り込む。
- テストすべき一連の流れ(このまま検証項目にする):
  1. 商品仕入れ(現実世界。トキワはまだ無関係)
  2. 仕入れ伝票と商品が手元に揃う
  3. **商品登録**(仕入れ伝票を見ながら) ← ここで写真を登録
  4. 登録内容の**確認・修正・削除** ← **削除時は写真ファイルも一緒に削除**
     (DB/ディスクを圧迫させない。孤立画像ファイルを残さない)
  5. 顧客を登録し、その商品を購入 ← レジで商品にカーソル/クリックすると写真が見えるか
  6. 顧客詳細の購入履歴でも、カーソル/クリックで写真が見えるか
  7. **返品した時の動作確認** ← 在庫に戻った後も画像が正しく見えるか
- 宝飾ナビ側のデータ: d_item.strpicfilename(商品ごとの画像ファイル名) + d_item_pic(追加画像82件)。
  **画像ファイル本体が吸い出しデータに含まれているか要確認** → 含まれていれば
  ファイル名で紐づけてそのまま移行できる。無ければ宝飾ナビの会社に画像フォルダの提供を依頼。
- 実装: products に画像パス(複数可)、商品詳細・在庫一覧・レジ・購入履歴でサムネイル表示、
  削除時は画像ファイルも削除。B-6(修理写真)とアップロード基盤(スマホ撮影対応)を共用。

### B-1. 返品・訂正機能
- レジ画面で日付や顧客名で過去の会計を呼び出し、行単位の削除 or 伝票ごと削除(返品)できる。
- **宝飾ナビの不満**: 訂正のたびに黒/赤の相殺行が積み重なり、3回直すと
  「黒赤黒赤黒赤正」のように非常に見にくい。
- **トキワの方針**: 画面には「最終的に正しいデータ」だけを表示する。
  取消・訂正の経緯は内部に監査用として保持するが、既定では見せない(必要な時だけ展開)。
- **適用範囲は売上が表示される全画面**(2026-07-15 追記):
  - 顧客詳細の購入履歴一覧 ← 明示要望。取消済み・訂正前の行は出さない
  - 日報・売上伝票明細表・CSV出力
  - ホームのタイル集計、購入額ランキング等の分析系
  - 実装方法: 取消・訂正は sales_slips/sale_lines に「無効フラグ(voided)」等を立て、
    表示・集計系のクエリは共通で無効行を除外する(画面ごとの個別対応にしない)。

### B-2. ポイント機能の拡張(要カードリーダー読み書き連携)
- レジ画面: ポイントを**任意で追加**できる。
- ルール: **ポイントで支払った会計にはポイントを付けない**。
- ポイント編集画面(レジとは別): カードを忘れたお客様に、レジを打たずに
  ポイントだけ追加・修正できる画面。カード読み取り・書き込みと連動。

### B-3. マスタ管理画面
- 担当者・仕入先・分類・ブランド・石・地金・動機・場所・地区 等のマスタを管理する画面。
- マスタの種類が多いので、設定画面に全部並べると見にくい。
  **カテゴリ分け+すぐ選べるナビ**(例: 左に種類リスト、右に内容)で設計する。

### B-4. 検索・分析メニューの拡充(左メニューに追加)
- 誕生日検索(誕生月のお客様一覧 → DM・お声がけへ)
- 購入順位(累計・期間別の上位顧客ランキング)
- ランク検索(ランク別の顧客一覧)

  ※検索結果→チェック→ラベル印刷 の流れは既存のラベル印刷(24面)を再利用。

### B-6. 修理お預かり票に写真を載せる(+撮影フローの改善) ※B-7の基盤を共用、実装コスト小
- 要望: 預かり品の写真を修理伝票に載せたい。ただし「カメラで撮る→PCに取り込む→添付」は手間。
- **改善案(推奨): スマホから直接登録**。トキワは店内LANのWebアプリなので、
  スマホ/タブレットのブラウザで修理伝票を開き、「写真を追加」ボタン→その場で撮影→
  そのままサーバーに保存(PCへの取り込み作業ゼロ)。
  - 実装: `<input type="file" accept="image/*" capture="environment">` + アップロードAPI
    (/api/upload)。保存先は data/photos/(gitignore)。repairs に写真パス列を追加。
    印刷時は伝票に縮小画像を配置。サイズは長辺1200px程度に自動縮小(容量対策)。
  - 運用: 受付時にレジPCで伝票を作る→スマホで同じ伝票を開いて撮影、または
    スマホだけで受付(店内共有モードで修理登録は許可済み)。
- 将来のカード連携と同様、店内LANが活きる機能。

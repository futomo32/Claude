# トキワ 本番移行(go-live)チェックリスト

宝飾ナビ → トキワの正式運用切替時に、上から順に実施する手順。実データは個人情報のため
`data/real/` は絶対にコミットしない(.gitignore 済み)。

## 0. 事前準備
- [ ] 本番機(Windows単機)に最新のコードを配置(`git pull` またはUSB配布)
- [ ] Python3 が動くことを確認(`python3 --version`)
- [ ] 宝飾ナビのCSV一式を `data/real/csv/` に配置
- [ ] 商品画像一式を `data/real/images/` に配置(8,094枚 / 約738MB)

## 1. 取り込む/取り込まないの判断
- [ ] **不明在庫の除外**: 消したい商品番号を `data/real/削除商品番号.txt` に列挙
      → `python3 scripts/check_delete_list.py` でプレビュー(重複・販売履歴ありを警告)
- [ ] **売掛の扱い**: 古い売掛を持ち込まないなら、取込時に `--no-receivables` を付ける
      (紙の売掛は運用開始後に「＋売掛を追加」で手入力)。持ち込むなら付けない。

## 2. 本番DBの構築(再取込)
- [ ] `python3 scripts/import_csv.py data/real/csv`
      (売掛を入れないなら `python3 scripts/import_csv.py data/real/csv --no-receivables`)
- [ ] 取込ログの件数(customers / products / slips / lines 等)が想定どおりか確認

## 3. 起動と表示確認
- [ ] `python3 server/app.py` で起動し、ブラウザで開く
- [ ] ログイン(管理者)→ 顧客検索・在庫一覧・レジ・日報が表示されるか
- [ ] 商品写真が出るか(商品詳細・在庫サムネ)
- [ ] 会計を1件テスト → 在庫が減る・購入履歴に載る・日報に反映(テスト後は取消 or DB差戻し)

## 4. ログインユーザーと権限
- [ ] 「設定・マスター → ログインユーザーと権限」で担当者を登録・役割設定
      (管理者/社員/パート。パートは仕入額・在庫画面・設定が見えない)
- [ ] 各自の初回ログインでパスワードを設定
- [ ] レジの「会計担当」に出す人を担当者マスタで「レジ表示ON」に(番号順に並ぶ)

## 5. 運用開始後の定期作業
- [ ] **毎営業日/締め時**: `python3 scripts/backup_db.py` でバックアップ
      (`db/backups/tokiwa_YYYYMMDD_HHMMSS.db` に一貫性コピー。サーバー起動中でも安全)
- [ ] バックアップは別媒体(USB/クラウド)にも退避
- [ ] 日報照会で当日の売上・現金締めを確認

## 補足
- 売掛を一旦空にしたい場合(取込後にクリア): `python3 scripts/clear_receivables.py`
  (バックアップ自動取得＋確認。`--with-history` で入金履歴も削除)。ただし再取込で復活するため、
  恒久的に空で始めるなら 1. の `--no-receivables` を使う方が確実。
- 実データ `data/real/` はこの開発環境からは直接置けないため、本番機側で配置する。

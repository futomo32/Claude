# トキワ 本番移行(go-live)チェックリスト

宝飾ナビ → トキワの正式運用切替時に、上から順に実施する手順。実データは個人情報のため
`data/real/` は絶対にコミットしない(.gitignore 済み)。

## 0. 事前準備
- [ ] 本番機(Windows単機)に最新のコードを配置(`git pull` またはUSB配布)
- [ ] Python3 が動くことを確認(`python3 --version`)
- [ ] 宝飾ナビのCSV一式を `data/real/csv/` に配置 ← **取込元はこちら**
- [ ] 11台帳の xlsx(11ファイル)を `data/real/xlsx/` に配置 ← 取込には使わないが**答え合わせ用**
- [ ] 商品画像一式を `data/real/images/` に配置(8,094枚 / 約738MB)

```
data/real/
  csv/                … 生ダンプ(114テーブル)。★import_csv.py が読むのはここだけ
  xlsx/               … 11台帳(まとめ版)。件数の答え合わせに使う
  images/             … 商品写真
  削除商品番号.txt     … 在庫から消す商品番号
```

## 1. 取り込む/取り込まないの判断
- [ ] **不明在庫の除外**: 消したい商品番号を `data/real/削除商品番号.txt` に列挙
      → `python3 scripts/check_delete_list.py` でプレビュー(販売履歴ありなどを警告)
      ```
      104714              商品番号だけ。これが基本
      104714,72000        商品番号＋仕入価格。同じ番号で在庫が2件以上ある時に使う
      01-104714           商品キー。その1件だけを狙い撃ち(価格でも区別できない時)
      ```
      **消えるのは「状態が在庫」のものだけ**です(売上・返品・受託は必ず残る)。
- [ ] **★「番号だけでは決まらないもの」を片付ける**(2026-09-01 追加)
      `check_delete_list.py` が**同じ番号で在庫が2件以上ある番号**を一覧に出し、
      **そのまま貼れる形**(`104714,72000`)で候補を表示する。ここが0件になれば、
      リストの指定はすべて1件に決まっている。
      **読めない行・価格が一致しない行も警告に出る**ので、必ず目を通すこと
      (黙って無視されると「消したつもりで消えていない」が起きるため)。
- [ ] **売掛の扱い**: 古い売掛を持ち込まないなら、取込時に `--no-receivables` を付ける
      (紙の売掛は運用開始後に「＋売掛を追加」で手入力)。持ち込むなら付けない。

## 2. 本番DBの構築(再取込)
- [ ] `python3 scripts/import_csv.py data/real/csv`
      (売掛を入れないなら `python3 scripts/import_csv.py data/real/csv --no-receivables`)
- [ ] 取込ログの件数(customers / products / slips / lines 等)が想定どおりか確認
- [ ] **★取込ログに出る「警告」を必ず読む**(2026-08-29 追加)
      - `※m_◯◯: 列名が想定と違うため自動判定` … 読み替えた列が正しいか確認する
      - `[警告] m_◯◯: コード/名前の列が見つかりません` … **その対応表が空のまま進んでいる**
      - `※脇石の石種コードのうち N件は石マスタに見つからず` … 件数が多ければ対応表が違う
- [ ] **新しく取り込む4項目が入ったか確認**(2026-09-01の取込が最後の機会)
      ```
      python3 -c "import sqlite3;c=sqlite3.connect('db/tokiwa.db');\
      [print(q, c.execute('SELECT COUNT(*) FROM '+t+\" WHERE COALESCE(\"+q+\",'')<>''\").fetchone()[0]) \
       for t,q in [('products','tag_name'),('products','sub_category'),('products','sub_stone'),\
                   ('products','sub_carat1'),('customers','dm_note')]]"
      ```
      目安: tag_name 約48% / sub_category 約96% / sub_stone 約33% / sub_carat1 約41% / dm_note 約33%。
      **0件のものがあれば取り込めていない**ので、そのまま進まず相談すること。
- [ ] **★11台帳と件数を突き合わせる**(2026-09-01 追加。取りこぼしの最終確認)
      **`ツール\データの調べもの\台帳の行数しらべ.bat`** をダブルクリック
      (コマンドでやるなら `python3 scripts/diag_real_xlsx.py`)
      台帳ごとの行数だけが出る(中身の値は表示しないので実データでも安全)。
      上の取込ログの件数と見比べる。
      - **顧客・商品・売掛・ポイントは一致するはず** … ズレたら取りこぼしを疑う
      - **販売台帳と処方箋はズレて正常** … 販売は伝票+明細に分けている。
        処方箋は宝飾品の誤登録を除いている

## 2b. ★xlsx にしか無い情報が無いか確かめる(2026-09-01 追加)
トキワの取込元はCSVで、xlsx(11台帳)は使っていない。「CSVの方が情報量が多いはず」
という前提で進めてきたが、**実測していなかった**。ここで確かめる。

- [ ] **`ツール\データの調べもの\台帳の列くらべ.bat`** をダブルクリック
      (コマンドなら `python3 scripts/diag_xlsx_vs_csv.py`。数分かかる)
- [ ] **★に出た列**を仕分ける。次の2つは取りこぼしではない:
      - 計算で作った列(経過月・粗利率など)… CSVに無くて当然
      - 2つの列を繋げた列(商品キーなど)  … CSVでは2列に分かれているだけ
- [ ] 残ったものが**本当の取りこぼし候補**。相談すること

> **急ぎではない。**宝飾ナビの契約は9月いっぱい残っているので、漏れが見つかっても
> **9月中なら取り直せる**。ただし**やらないまま10月に入らないこと**(そこが期限)。
> 取込を止めてまで先にやる必要はない。営業開始を優先してよい。

## 4. ログインユーザーと権限
- [ ] 「設定・マスター → ログインユーザーと権限」で担当者を登録・役割設定
      (管理者/社員/パート。パートは仕入額・在庫画面・設定が見えない)
- [ ] 各自の初回ログインでパスワードを設定
- [ ] **★管理者を2人つくる**(2026-08-17 決定。理由は feedback-backlog.md の決定事項)
      管理者は**自分のパスワードを忘れた時に自力で戻せない**。1人だけだと、その時点で
      誰もログインできず営業が止まる。お互いにリセットし合える状態を必ず保つ。
- [ ] **★2人目の管理者で実際にログインできることを確認**(作っただけで終わらせない)
- [ ] **宝飾ナビから取り込まれた不要なログインユーザーを「無効」にする**
      取込は `d_systemuser` のユーザーを全部持ってくる(パスワードは取り込まないので
      全員「未設定」)。使わない人は**編集 → 有効のチェックを外す**。無効にすると一覧から
      隠れる。**削除はしない**(同じIDを作り直せると、監査記録の名前と別人が混ざるため)
- [ ] レジの「会計担当」に出す人を担当者マスタで「レジ表示ON」に(番号順に並ぶ)

## 4b. 紙の売掛を登録する(`--no-receivables` で取り込んだ場合)
紙の台帳が正式版のため、宝飾ナビの売掛は持ち込まず、**紙から入れ直す**。

- [ ] 件数が数十件なら**画面から手入力**(顧客詳細 → ＋売掛を追加)。
      顧客を目で選べるので取り違えが起きない。**これが一番安全**。
- [ ] 件数が多いなら **`ツール\売掛の一括入力\`** を番号順に使う
      1. `1_入力用ファイルを作る.bat` → `data\real\売掛入力.csv` をExcelで開いて打ち込む
      2. `2_下読み_取り込まない.bat` → **合計金額を紙の合計と突き合わせる**
      3. `3_取り込む.bat` → 登録(バックアップ自動取得。トキワは止めてから)
- [ ] **顧客が1人に決まらなかった行**(`data\real\売掛_要確認.csv`)を直して流し直す
      同姓同名は電話を入れると絞れる。顧客IDが分かるならIDが確実。
- [ ] 登録後、**売掛の合計が紙と1円まで合うか**を確認する

## 補足
- 売掛を一旦空にしたい場合(取込後にクリア): `python3 scripts/clear_receivables.py`
  (バックアップ自動取得＋確認。`--with-history` で入金履歴も削除)。ただし再取込で復活するため、
  恒久的に空で始めるなら 1. の `--no-receivables` を使う方が確実。
